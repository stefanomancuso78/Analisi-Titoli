# Autonomous research H24

The existing Sites application keeps D1 and R2. GitHub Actions, on the existing public repository, is the independent scheduler (`autonomous-research.yml`, four opportunities per hour). After useful persisted progress, a run can dispatch its successor using the built-in short-lived GitHub token (Actions write permission); this avoids waiting for the next cron tick during recovery. No progress or an open transport circuit stops the continuation chain; the cron remains the wake-up/backstop. Parent run IDs are recorded in the heartbeat. GitHub schedules can be delayed or skipped; this is not an execution SLA. Public repository inactivity can cause GitHub to disable scheduled workflows after 60 days: monitor workflow status as well as the persisted heartbeat.

A short-lived GitHub OIDC token authenticates POST `/api/worker`. Sites verifies the RS256 signature against GitHub's fixed JWKS endpoint and checks issuer, audience, expiry, repository, main branch, workflow path and event. There are no permanent worker credentials, user passwords or paid model keys. The endpoint exposes only bounded worker operations; it does not grant general admin access.

Each run restores a pinned, checksum-verified Apache-2.0 Qwen3-4B quantized model and MIT llama.cpp CPU runtime. It reads acquired text locally on the standard GitHub runner. Production documents, notes and model responses are not written to public logs/artifacts; only counts, symbols, result IDs and operational errors are logged. Review chunks and source hashes are checkpointed in D1. Local inference may be slow; no API fallback or paid runner is enabled.

A 20-minute fenced lease prevents concurrent dossier review. Chunks are sequential, exact-text hashes and quotation substrings are checked, and checkpoints survive crashes. A replacement worker resumes the first unread chunk after expiry. Completion requires every acquired document and a final, valid multi-document reassessment through the unchanged frozen research validator. Missing context, wrong quotes or an interrupted model response remain incomplete. Model output is not independent human verification or proof of economic causality. Final revisions use the existing append-only research protocol; old predictions and experiment protocols are untouched.

Live-load validation keeps the ordinary budget of 24 new research requests/day even while backlog is high. Arrival pressure is measured and alarmed rather than silently setting intake to zero. The H24 scheduler calls admission planning independently of whether there is already evidence to review, at most hourly; provider rate limits and retry/backoff remain enforced. Acquired dossiers have priority. Provider failures retain per-job retry/backoff and bounded acquisition; there is no blind reset of blocked work. Failed review attempts have separate exponential delays and remain evidence-ready rather than falsely reviewed.

GET `/api/autonomous-status` requires normal visitor authentication. The StokIQ connector supports `list_research({autonomous_status:true})`. Counts, 24-hour admissions/revisions/closures, hourly revisions, oldest age, heartbeat/resources, provider attempts, run events and explicitly conditional drain estimates are exposed. Alerts include missing heartbeat, reviews stalled and intake exceeding closures. GitHub sends normal workflow-failure notifications according to the owner's notification settings; no email service or extra paid task is added.

Operational stop: disable the GitHub workflow with the repository Actions controls. Resume by enabling it and dispatching a run from main. No database reset is needed. Existing ChatGPT automation is a complementary observer, not an execution dependency. Its work remains subject to the same research lease and citation validation.

Validation requires a real OIDC-authenticated runner heartbeat, actual model text review checkpoint(s), saved validated revisions and subsequent scheduled execution. A deployment or green CI alone does not establish continuous throughput. Report incomplete free-model reviews and source gaps explicitly; a backlog ETA is unavailable until actual closures have been measured over a meaningful interval.

CPU stream engine v3 uses 4,000-character source chunks, orders eligible dossiers by source publication date and resumes saved chunks when their dossier is next, and streams schema-constrained output with a bounded six-minute deadline. Old in-flight leases retain their original chunk size and namespace; old attempt receipts remain available. A reviewed dossier still requires complete source coverage and the unchanged research validator. Final inference reads every saved summary and a bounded, diverse verbatim citation catalog.

## Independent daily-close refresh
The verified scheduler heartbeat also runs the bounded market sweep, separately from inference and the research evidence queue. A shared one-hour gate and fenced three-minute lease prevent concurrent/repeated sweeps. Each due sweep refreshes SPY and XLK plus at most four symbols (AMD and three rotating eligible open Test 4 names). The five current Test 4 names are covered within two due sweeps. Attempts and provider results are exposed in autonomous status; a successful HTTP response is not a guarantee that the latest trading close is available. Missing dates remain null and no historical prediction or protocol is changed.

## News priority
New admissions, source collection, review claims and connector queues prefer the most recent verified source publication date (falling back to the original assessment date), then existing importance. Download time does not make an old announcement new. Older partial readings remain saved; a running fenced lease is not interrupted. Retry/backoff and exact evidence validation are unchanged. A continuing stream of newer eligible news may delay older backlog.

## Optional Gemini provider
Owner-only setup: `/gemini`, linked from the root administration console. The API key is encrypted in the existing credential vault, never returned to browsers or GitHub runners. The signed unattended worker can request bounded server-side inference using a fixed Google endpoint and JSON schemas. All source coverage, exact citation and frozen reassessment checks remain enforced. Actual model identifiers are preserved on chunk notes and final events; CPU remains the fallback. Gemini is disabled until an owner saves a key and explicitly confirms a Google project without billing and enables Gemini. The system cannot independently attest the Google billing tier. No StokIQ dossier or daily-request cap: measure actual daily attempts and completed dossiers, respecting provider quota errors and backoff. Per-request payload/output limits remain enforced; no automatic paid upgrade. Model listing authenticates without generating content. No production inference can be verified before the owner supplies the key.

## Resumable final synthesis
After complete source coverage, generate and checkpoint each economic text field separately with bounded output, then classify and validate exact multi-document citations. A partial synthesis cannot close jobs; changed evidence invalidates the fenced draft. Workload timeouts retain notes and draft fields and do not trip the global provider-outage circuit. Legacy timeout-blocked dossiers receive a versioned recovery attempt with their previous attempt history retained. Successful checkpoints clear consecutive provider outages. Long local calls retain heartbeat-based lease renewals, a twelve-minute request deadline and a bounded twenty-eight-minute work budget. Runtime phases distinguish partial progress, no progress and a validated revision. No frozen experimental functions or historical results are changed.
