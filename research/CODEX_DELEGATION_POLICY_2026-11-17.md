# StokIQ — ownership and delegation policy (17 November 2026)

## Objective
Build and prospectively validate a continuously improving prediction system from source-attributed, first-known-at economic information, news, and post-prediction market outcomes. Eventually support human-governed buy/hold/sell decisions for private and professional investors. This policy authorizes no real orders.

## Roles
- **ChatGPT conversation and connected GitHub/StokIQ tools:** primary architecture, investigation, implementation and testing. Modify code, investigate sources, build deterministic extractors, develop and test versioned learning challengers, run GitHub CI and inspect read-only operational metrics. Separate CI proof from real production proof.
- **Codex:** only work that cannot be performed with connected tools and demonstrably requires authenticated hosting, local shell/browser, or special artifact generation. Primarily deployment of an exact approved commit to the existing StokIQ Sites project, authenticated smoke checks, or a narrowly scoped shell-only task.
- **Quota policy:** plan for up to **75% of any available Codex usage for genuinely Codex-only StokIQ work**, not as a guaranteed quota, automatically assigned reservation, or authorization to spend all available usage. The user expects Codex access to resume the evening of **20 November 2026**. No claims of executing Codex tasks before tools are available.
- Codex should not repeat GitHub investigations, refactor autonomously, invent financial forecasts, alter frozen experiments, create other services or bypass provider backoffs.
- No paid providers or extra inference services without explicit user authorization.

## Strict release handoff
1. Exact merged full SHA on main, green CI and build for the exact SHA, no conflicting branch.
2. Verified encrypted backup and compatible schema. Do not reset, migrate, alter D1/R2 bindings, passwords, credentials or secrets.
3. One deployment to the existing Sites project only if the SHA is not yet live.
4. Authenticated website and API checks: Tests 1–4 including the four selected prospective Test 4 cases, immutable forecasts and six original portfolios, model shadow status, genuine quote/provider dates, source acquisition evidence, backup and permissions.
5. No forced source scans, no next_poll/backoff bypass, no actual trading. Record source HTTP status, documents found and truly acquired.
6. Report Sites revision, exact SHA, UTC/Dubai timestamp, measured checks and unresolved errors. Stop on integrity mismatch.

## Learning invariants
- Central timestamped, source-attributed evidence must remain auditable.
- Train only on matured outcomes from preassigned training folds; evaluate only on independently preassigned prospective examples predicted before outcome.
- Models are versioned shadow challengers until evidence, benchmark and cost comparison, drift checks and independent manager review justify manual promotion.
- Operational data acquisition and research follow-up admission use real throughput and enforce provider license/rate limits.
- No deployment, Codex run or automatic quota allocation is created by this policy document.
